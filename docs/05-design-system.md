## 1. Identidad de Marca

SmartCaña no compite en la categoría de "software agrícola tradicional". Compite en la categoría de **plataformas AgTech inteligentes**. Su identidad debe reflejar precisión quirúrgica, inteligencia artificial, sustentabilidad y una obsesión por la experiencia de usuario propia de las mejores empresas tecnológicas globales.

### 1.1 Propósito

Empoderar a cada productor cañero con inteligencia de datos para transformar la agricultura familiar-industrial en una operación de precisión, rentable y sostenible.

**Justificación:** El ADN del producto es devolverle al productor el control de su negocio a través de datos que antes no existían o estaban fragmentados. No se trata de "digitalizar papel" sino de habilitar una nueva forma de tomar decisiones.

### 1.2 Misión

Democratizar el acceso a la agricultura de precisión para productores de caña de azúcar, combinando inteligencia artificial, georreferenciación y diseño de clase mundial en una plataforma que cualquier productor pueda usar sin capacitación técnica.

### 1.3 Visión

Convertir a SmartCaña en el estándar de gestión inteligente de caña de azúcar en Latinoamérica, integrando la cadena completa —campo, ingenio, mercado— en un ecosistema digital único.

### 1.4 Personalidad de Marca

| Atributo | Manifestación |
|---|---|
| **Preciso** | Cada elemento UI tiene un propósito. No hay decoración gratuita. Cada número, gráfico y mapa es exacto. |
| **Inteligente** | La IA no es una feature decorativa: está integrada en el flujo de trabajo, sugiriendo, prediciendo y alertando. |
| **Confiable** | La plataforma es sólida, predecible, estable. El productor debe sentir que puede tomar decisiones de miles de dólares basándose en SmartCaña. |
| **Simple** | La complejidad agrícola se oculta detrás de interfaces limpias. Un productor de 60 años debe poder usarla sin leer un manual. |
| **Moderno** | No parece un sistema agrícola. Parece un producto SaaS premium. Los productores deben sentirse orgullosos de usarlo. |
| **Sostenible** | Cada decisión optimizada es una decisión más verde: menos agua, menos fertilizante, menos combustible, más caña por hectárea. |

### 1.5 Tono de Comunicación

| Contexto | Tono | Ejemplo (no literal) |
|---|---|---|
| UI / Labels | Directo, minimalista | "Rendimiento estimado: 72.4 t/ha" |
| Notificaciones | Informativo, accionable | "Helada pronosticada para mañana. ¿Desea programar alerta?" |
| Chat IA | Conversacional, profesional | "Según los datos históricos, esta parcela rinde un 18% menos que el promedio. ¿Quiere analizar posibles causas?" |
| Errores | Humano, sin jerga técnica | "No pudimos cargar los datos del campo. Reintentamos automáticamente." |
| Onboarding | Cálido, guiado | "Bienvenido a SmartCaña. En 5 minutos tendrá su primer campo mapeado." |
| Reportes | Formal, data-driven | "Informe de campaña 2026/2027 — 15% de incremento en eficiencia de cosecha." |

### 1.6 Valores

1. **Los datos primero** — Cada decisión debe estar respaldada por datos. No opiniones, no suposiciones.
2. **Simplicidad radical** — Si una pantalla confunde al usuario, está mal diseñada. Se rediseña.
3. **Precisión sobre cantidad** — Preferimos 3 KPIs exactos a 30 métricas irrelevantes.
4. **El productor es el centro** — Todo feature debe responder a un problema real documentado en campo.
5. **Sustentabilidad en cada línea** — Optimizar recursos no es solo rentable, es responsable.
6. **Mejora continua** — La plataforma aprende del usuario y evoluciona con él.

## 2. Branding

### 2.1 Concepto General

La identidad visual de SmartCaña se construye sobre tres conceptos fundamentales:

- **Caña de azúcar** como símbolo de origen y propósito
- **Precisión / dato** como símbolo de inteligencia y tecnología
- **Crecimiento / trayectoria** como símbolo de mejora continua y sustentabilidad

La marca debe funcionar tanto en contextos digitales (plataforma SaaS) como físicos (fichas de campo, equipamiento, camiones) manteniendo coherencia en todos los puntos de contacto.

### 2.2 Logotipo

**Estructura:**
- Logotipo compuesto por **isotipo + tipografía**, en una disposición horizontal (predeterminada) o vertical (variante compacta).
- El isotipo se ubica a la izquierda del nombre "SmartCaña".
- La "S" de Smart y la "C" de Caña comparten una misma barra ascendente, simbolizando la conexión entre tecnología y agricultura.

**Variantes:**
- **Horizontal completa:** Isotipo + "SmartCaña" — Uso principal en web, app, documentación.
- **Compacta:** Solo isotipo — Favicon, avatar, app icon, header móvil.
- **Vertical:** Isotipo sobre "SmartCaña" — Uso en espacios reducidos verticales.

### 2.3 Isotipo

**Descripción conceptual:**

El isotipo representa una **caña de azúcar vista desde arriba, estilizada como un marcador de datos geográficos**.

- El tallo de la caña se convierte en una línea vertical que evoca un pin de mapa.
- Las hojas se transforman en tres hojas geométricas ascendentes, una más corta que la siguiente, representando el crecimiento progresivo y la mejora continua de los cultivos.
- En la base, un punto representa el **dato** —el origen de toda decisión inteligente— y evoca un punto geográfico en un mapa.

**Significado cromático:**
- El tallo utiliza un verde profundo (representa el cultivo, la tierra, la vida).
- Las hojas degradan de verde a un tono ámbar-dorado (representa la maduración de la caña, el punto óptimo de cosecha, el valor económico).
- El punto base utiliza el acento naranja (representa el dato, la tecnología, la acción).

**Forma general:**
- Silueta compacta, geométrica, que funciona a 16 px (favicon) como a 256 px.
- Ángulos precisos de 45° y 90° que remiten a coordenadas geográficas y datos estructurados.
- Sin curvas orgánicas. Todo es intencional, exacto.

### 2.4 Imagotipo

El imagotipo combina el isotipo con la palabra "SmartCaña" en la tipografía primaria (Inter Bold).

- **"Smart"** en peso Medium, tracking normal.
- **"Caña"** en peso Bold, con una tilde que puede integrarse como un pequeño elemento gráfico (un punto cuadrado, no redondo, consistente con la identidad geométrica).
- La palabra completa usa el color del tallo principal.
- Altura de la tipografía igual a la altura del isotipo.

### 2.5 Favicon

El favicon es el isotipo simplificado a su mínima expresión:
- Solo la línea vertical (tallo) y el punto base.
- Sin hojas a 16 px (desaparecen por legibilidad).
- A 32 px y 48 px, las hojas reaparecen sutiles.

Se generan todas las variantes estándar:
- `favicon.ico` (16×16, 32×32)
- `icon.png` (192×192, 512×512) — PWA
- `apple-touch-icon.png` (180×180)
- `safari-pinned-tab.svg` (monocromático)

### 2.6 Aplicación sobre Fondos

| Fondo | Logotipo | Isotipo |
|---|---|---|
| Claro (#F7F7F5) | Versión completa color | Verde profundo + ámbar |
| Oscuro (#0F0F0F) | Versión completa blanco/verde claro | Blanco + verde claro |
| Color (verde brand) | Versión completa blanco | Blanco |
| Fotografía | Versión completa blanco con sombra sutil | Blanco |

En fondos oscuros, el ámbar de las hojas se reemplaza por un verde lima más luminoso para mantener legibilidad.

### 2.7 Modo Claro y Oscuro

El logotipo tiene dos variantes binarias:
- **Modo claro:** Isotipo con verde profundo, ámbar, naranja. Texto en gris oscuro.
- **Modo oscuro:** Isotipo con verde claro, verde lima, blanco. Texto en blanco.

La plataforma respeta `prefers-color-scheme` y permite al usuario elegir manualmente.

## 3. Paleta de Colores

### 3.1 Filosofía de Color

SmartCaña utiliza el color como un sistema de comunicación, no como decoración. Cada color tiene un significado funcional y se aplica de manera consistente en toda la plataforma.

La paleta está inspirada en:
- **El paisaje cañero:** verdes profundos, ámbares dorados, naranjas de atardecer tucumano.
- **La tecnología premium:** grises fríos precisos, blancos limpios, acentos vibrantes pero controlados.
- **La sustentabilidad:** tonos naturales, no saturados, que transmiten madurez y responsabilidad.

## 4. Tipografía

### 4.1 Selección Tipográfica

| Rol | Fuente | Peso | Justificación |
|---|---|---|---|
| **Primaria** | Inter | Light (300), Regular (400), Medium (500), SemiBold (600), Bold (700) | Diseñada por Rasmus Andersson para la interfaz de Figma. Excelente legibilidad en pantalla, kerning consistente, soporte completo de caracteres latinos con acentos (fundamental para el español). Es la fuente de Vercel, Linear, Arc Browser. Transmite precisión técnica y neutralidad. |
| **Secundaria** | Geist Mono | Regular (400), Medium (500), Bold (700) | Diseñada por Vercel. Se usa exclusivamente para datos numéricos (KPIs, métricas, tablas de rendimiento) por su alineación monoespaciada perfecta y su estilo técnico pero amigable. |
| **Display** | Inter Display | Bold (700), ExtraBold (800) | Variante optimizada para titulares grandes. Solo en dashboard principal y landing pages. Se carga condicionalmente. |

**Fallback stack:**
- Inter → `-apple-system`, `BlinkMacSystemFont`, `Segoe UI`, `Roboto`, `Helvetica Neue`, `Arial`, sans-serif
- Geist Mono → `SF Mono`, `SFMono-Regular`, `Menlo`, `Monaco`, `Consolas`, `Liberation Mono`, `Courier New`, monospace

### 4.4 Reglas de Tipografía

1. **Máximo 2 fuentes.** Inter para todo el contenido, Geist Mono solo para datos numéricos. No hay excepciones.
2. **Geist Mono se usa exclusivamente** para: KPIs, valores en tablas, métricas en gráficos, timestamps, coordenadas, precios, rendimientos, superficies. Si no es un número significativo, no usa Geist Mono.
3. **Tracking negativo en titulares** mejora la legibilidad. A mayor tamaño, más tracking negativo.
4. **Line-height generoso** para cuerpo (1.5) mejora escaneabilidad. Para titulares, line-height ajustado (1.1-1.2) da un aspecto más premium.
5. **Sin mayúsculas sostenidas** en UI. Todo en sentence case. Las etiquetas pueden ser en uppercase solo si son badges o tags de estado.
6. **Fluid type** en dashboard: los tamaños se escalan con `clamp()` para adaptarse a viewports sin breakpoints. Ejemplo: `font-size: clamp(0.875rem, 1vw + 0.5rem, 1rem)`.

## 5. Iconografía

### 5.1 Familia de Iconos

**Lucide Icons** es la familia oficial de SmartCaña.

**Justificación:**
- Diseño consistente con líneas de 2px, puntas redondeadas, geometría limpia.
- Cobertura completa de iconos necesarios para agricultura, datos, mapas, IA, navegación.
- Totalmente open source (MIT).
- Compatible nativa con React (paquete `lucide-react`).
- La misma familia usada por shadcn/ui, lo que garantiza coherencia visual con el design system base.

### 5.2 Sistema de Tamaños

| Contexto | Tamaño | Pixel |
|---|---|---|
| Iconos en navegación / sidebar | `icon-sm` | 16×16 |
| Iconos en botones, inputs, tabs | `icon-md` | 20×20 |
| Iconos en cards, alertas, badges | `icon-md` | 20×20 |
| Iconos en empty states | `icon-lg` | 32×32 |
| Iconos en mapas, markers | `icon-xl` | 24×24 |
| Iconos decorativos (illustrations) | `icon-2xl` | 48×48+ |

**Regla:** Los iconos no se escalan arbitrariamente. Siempre usan una de las 5 medidas definidas.

### 5.3 Criterios de Uso

1. **Funcional, no decorativo.** Cada icono comunica una acción o un estado. Si un icono no añade información, no se usa.
2. **Acompañado de texto** siempre que sea posible. En navegación principal, el icono + label. Solo icono es aceptable en header compacto o mobile.
3. **Consistencia semántica.** El icono de "campo" (sprout o terrain) es siempre el mismo en toda la plataforma. No mezclar variantes de distintos sets.
4. **Colores semánticos.** Los iconos toman el color del contexto: `text-secondary` por defecto, `brand-500` para activo, `error-500` para alertas, `ai-500` para funciones IA.
5. **Sin animación en iconos funcionales.** Los iconos no rotan, no brillan, no parpadean. Solo los iconos de carga (spinner) tienen animación.
6. **Iconos custom solo si es necesario.** Si Lucide no tiene el icono requerido (ej: caña de azúcar, parcela NDVI), se diseña un icono custom que siga exactamente el estilo de Lucide (stroke-width=2, round caps, round joins, 24×24 viewbox).

**Regla de spacing vertical:** Usar siempre múltiplos de 4px. No mezclar rem y px (usar rem para todo salvo bordes de 1px).

### 6.2 Grid

**Layout de Dashboard:**
- Sistema de **CSS Grid** (no flexbox para el layout macro).
- Columnas: 12-column grid flexible.
- Sidebar colapsable de 240px (expandida) / 64px (colapsada).
- Main content: 1fr.
- Gutter: `space-6` (24px).

**Caja de grid para dashboard (componentes):**
```css

```

| Componente | Columnas (desktop) | Columnas (tablet) | Columnas (mobile) |
|---|---|---|---|
| KPI Card | 3 | 6 | 12 |
| Mapa | 8 | 12 | 12 |
| Timeline / Actividad | 4 | 12 | 12 |
| Gráfico grande | 12 | 12 | 12 |

| Card de IA | 12 | 12 | 12 |
| Tabla | 12 | 12 | 12 |
| Metric widget | 4 | 6 | 12 |

### 6.3 Breakpoints

SmartCaña se diseña **mobile-first** pero se optimiza para **desktop**.

| Breakpoint | Min Width | Target |
|---|---|---|
| `xs` | 0 | Teléfonos pequeños (< 375px) |
| `sm` | 640px | Teléfonos grandes |
| `md` | 768px | Tablets en vertical |
| `lg` | 1024px | Tablets en horizontal, notebooks pequeños |
| `xl` | 1280px | Notebooks estándar |
| `2xl` | 1536px | Monitores de escritorio |

**Breakpoints de dashboard:**
- El dashboard cambia de 3 columnas a 2 columnas en `md`.
- El dashboard cambia de 2 columnas a 1 columna en `sm`.
- La sidebar se colapsa automáticamente en `lg` (pasa a `64px`) y se oculta en `md` (drawer overlay).

### 6.4 Border Radius

SmartCaña usa radios consistentemente sutiles. Esquinas agresivamente redondeadas no son consistentes con una identidad de precisión.

| Token | Valor | Uso |
|---|---|---|
| `radius-none` | 0 | Imágenes, mapas, elementos que ocupan todo el ancho |
| `radius-sm` | 4px | Inputs, botones, badges |
| `radius-md` | 6px | Cards, dropdowns, tooltips |
| `radius-lg` | 8px | Modales, sidebars, drawers |
| `radius-xl` | 12px | Tarjetas de mapa, dashboard widgets grandes |
| `radius-2xl` | 16px | Cards de landing page |
| `radius-full` | 9999px | Avatares, pills, badges de estado |

**Regla:** Preferir `radius-md` como default. Botones tienen `radius-sm`. Cards tienen `radius-lg`. Las esquinas redondeadas no deben superar 16px en ningún componente funcional.

### 6.5 Sombras

Las sombras son sutiles. SmartCaña no usa sombras dramáticas. En modo oscuro, las sombras se reemplazan por bordes y fondos elevados.

| Token | Valor | Uso |
|---|---|---|
| `shadow-sm` | `0 1px 2px 0 rgb(0 0 0 / 0.04)` | Hover de elementos, separación sutil |
| `shadow-md` | `0 4px 6px -1px rgb(0 0 0 / 0.06), 0 2px 4px -2px rgb(0 0 0 / 0.05)` | Cards de dashboard |
| `shadow-lg` | `0 10px 15px -3px rgb(0 0 0 / 0.08), 0 4px 6px -4px rgb(0 0 0 / 0.04)` | Modales, dropdowns |
| `shadow-xl` | `0 20px 25px -5px rgb(0 0 0 / 0.10), 0 8px 10px -6px rgb(0 0 0 / 0.05)` | Modales grandes, drawers |
| `shadow-ring` | `0 0 0 2px var(--brand-500)` | Focus ring de inputs y botones |

**Modo oscuro:** Las sombras se minimizan (casi desaparecen). En su lugar, los elementos elevados usan un borde sutil (`border-default`) y un fondo ligeramente más claro (`bg-elevated`). Esto elimina el efecto "flotante" que se ve mal en dark mode.

## 7. Componentes

### 7.1 Botones

**Filosofía:** Cada botón comunica una acción. No hay ambigüedad visual sobre qué hace un botón ni si se puede hacer clic.

**Variantes:**

| Variante | Uso | Fondo | Texto | Borde | Hover | Active |
|---|---|---|---|---|---|---|
| **Primary** | Acción principal en cada pantalla | `brand-500` | White | — | `brand-600` | `brand-700` |
| **Secondary** | Acción secundaria | `bg-subtle` | `text-primary` | `border-default` | `bg-surface` + shadow-sm | `bg-subtle` |
| **Outline** | Acción terciaria | Transparent | `text-primary` | `border-default` | `bg-subtle` | `bg-subtle` + border-strong |
| **Ghost** | Acción de baja jerarquía | Transparent | `text-secondary` | — | `bg-subtle` | `bg-subtle` + text-primary |
| **Danger** | Acción destructiva | `error-500` | White | — | `error-600` | `error-700` |
| **AI** | Acción de IA | `ai-50` | `ai-500` | `ai-200` | `ai-100` | `ai-100`+border-ai |
| **Link** | Navegación inline | Transparent | `brand-500` | — | Underline | Underline+brand-600 |

**Tamaños:**

| Tamaño | Altura | Padding X | Font Size | Icon Size |
|---|---|---|---|---|
| `xs` | 28px | 10px | 12px | 14px |
| `sm` | 32px | 12px | 14px | 16px |
| `md` (default) | 40px | 16px | 14px | 18px |
| `lg` | 48px | 20px | 16px | 20px |
| `xl` | 56px | 24px | 18px | 22px |

**Estados Visuales:**
- **Default:** Sombra sutil (`shadow-sm`) solo en primary.
- **Hover:** Elevación +1 (sombra aumenta), fondo más oscuro.
- **Active:** Escala 0.98 (hundimiento sutil), fondo más oscuro.
- **Disabled:** Opacidad 0.4, sin sombra, cursor not-allowed.
- **Loading:** Spinner replace icon o después del texto. Botón mantiene ancho para evitar layout shift.
- **Focus:** `shadow-ring` en brand-500 para primary, en border-strong para ghost/outline.

**Regla:** En cada pantalla solo hay **un** botón primary. Si hay dos acciones igual de importantes, se rediseña la pantalla.

### 7.2 Inputs

**Filosofía:** Inputs deben parecer editables incluso sin foco. El estado debe ser obvio en un vistazo.

**Estructura visual:**
```

│ ┌────────────────────────────────┐  │
│ │ Icono    Valor                  │  │
│ └────────────────────────────────┘  │
```

**Variantes:**

| Estado | Fondo | Borde | Texto |
|---|---|---|---|

| Hover | `bg-surface` | `border-strong` | `text-primary` |
| Focus | `bg-surface` | `brand-500` + shadow-ring | `text-primary` |
| Filled | `bg-surface` | `border-default` | `text-primary` |
| Error | `bg-surface` | `error-500` + shadow-ring(error) | `text-primary` |
| Disabled | `bg-subtle` | `border-default` | `text-tertiary` |
| Read-only | `bg-subtle` | `border-default` | `text-secondary` |

**Tamaños:**

| Tamaño | Altura | Padding X | Font Size |
|---|---|---|---|
| `sm` | 32px | 10px | 14px |
| `md` | 40px | 12px | 14px |
| `lg` | 48px | 16px | 16px |

**Elementos del input:**
- **Label:** text-sm, text-secondary, space-1.5 bottom gap.
- **Placeholder:** text-tertiary.
- **Helper text:** text-xs, text-tertiary, space-1 top gap.
- **Error text:** text-xs, error-500, space-1 top gap.
- **Icono izquierdo:** Siempre text-secondary, 20px, space-2 left.
- **Icono derecho / acción:** Clear button, password toggle, dropdown arrow.
- **Character counter:** text-xs, text-tertiary, alineado a la derecha.

**Inputs especiales:**
- **Search:** Icono lupa a la izquierda, clear button a la derecha cuando hay texto, border-radius circular (radius-full).
- **Textarea:** Misma estética, resize vertical only, altura mínima 80px.
- **Select:** Dropdown nativo estilizado o custom select con misma altura y padding que inputs md.
- **Date picker:** Input + calendario dropdown. Formato ISO localizado (dd/mm/aaaa).
- **Number:** Geist Mono font, sin flechas nativas de incremento (diseño custom).
- **Phone:** +54 prefix fijo, máscara de formato.

### 7.4 Tablas

**Filosofía:** Las tablas en SmartCaña son densas en datos pero visualmente livianas. El usuario debe poder escanear 100 filas en segundos.

**Estructura visual:**
```
┌─────────────────────────────────────────────────────┐
│  Column 1    Column 2    Column 3    Column 4   ...  │ ← Header fijo
│─────────────────────────────────────────────────────│
│  Data 1      Data 2      Data 3      Data 4      │ ← Row hover
│  Data 1      Data 2      Data 3      Data 4      │
│  Data 1      Data 2      Data 3      Data 4      │ ← Row selected
└─────────────────────────────────────────────────────┘
└─── Paginación / contador ───────────────────────────┘
```

**Especificaciones:**
- **Header:** text-xs, text-secondary, uppercase tracking-wider, weight medium. Sin fondo de header (solo borde inferior).
- **Rows:** Altura 48px (compact) o 56px (default). Borde inferior `border-default`.
- **Hover:** `bg-subtle` en toda la fila.
- **Selected:** `brand-50` en toda la fila.
- **Striped:** No usar. No es necesario con hover y espaciado adecuado.
- **Font:** Inter para texto, Geist Mono para números.
- **Sort indicator:** Flecha sutil en header cuando está ordenado.
- **Checkbox:** Solo en tablas con acciones batch.
- **Empty state:** "No hay datos" con icono, centrado en la tabla.
- **Paginación:** "Mostrando 1-20 de 156" + botones anterior/siguiente.

**Variantes:**
- **Simple:** Solo filas, sin header fijo. Para listas cortas (< 10 items).
- **Full:** Header fijo, scroll horizontal, sticky columns (primera columna + acciones).
- **Compact:** Altura de row 40px, texto text-xs. Para tablas de configuración.
- **Tree:** Filas expandibles con jerarquía. Para desglose de costos.

### 7.9 Charts / Gráficos

**Filosofía:** Los datos en SmartCaña se ven primero como gráficos, después como tablas. Cada gráfico cuenta una historia.

**Biblioteca:** Recharts.

**Tipos de gráfico:**

| Tipo | Uso | Variantes |
|---|---|---|
| **Line** | Tendencia de producción, rendimiento histórico | Simple, multi-serie, área rellena |
| **Bar** | Comparación entre parcelas, costos por categoría | Vertical, horizontal, stacked, grouped |
| **Area** | Precipitación acumulada, temperatura | Monocromático con gradiente |
| **Pie / Donut** | Distribución de costos, proporción de variedades | Donut con label central |
| **Radar** | Comparación multi-variable de parcelas | — |
| **Scatter** | Correlación rendimiento vs. lluvia | Con línea de tendencia |
| **Composed** | Serie temporal con barras + línea (clima) | — |

**Estilo visual:**
- **Sin gridlines** verticales. Gridlines horizontales sutiles (`stroke: border-default, strokeWidth: 1`).
- **Sin ejes** redundantes. Solo eje Y (labels) y eje X (categorical o temporal).
- **Tooltip:** Card flotante `bg-surface`, `shadow-lg`, con border-radius `radius-md`. Padding `space-3`. Formato de número con Geist Mono.
- **Legend:** Abajo del gráfico, horizontal, `text-xs`.
- **Animation:** Draw effect en línea, grow en barras. 500ms stagger por serie.
- **Empty state:** "No hay datos para este período" con icono.
- **Loading state:** Skeleton rectángulo con shimmer.
- **Responsive:** Auto-resize con contenedor responsivo.

**Altura:** 140px (puede variar según contenido).
**Padding:** space-5.

## 8. Dashboard

### 8.1 Filosofía del Dashboard

El dashboard de SmartCaña no es un "tablero de control genérico". Es el **centro de comando** del productor. Cuando abre la plataforma, debe ver en 3 segundos:

1. **¿Cómo está mi campo hoy?** (mapa + clima + alertas)
2. **¿Qué pasó recientemente?** (actividad + producción)
3. **¿Qué necesita mi atención?** (alertas + tareas pendientes)
4. **¿Cómo voy económicamente?** (costos + rendimiento)

### 8.3 Bloques del Dashboard

#### Bloque 1: KPIs (fila superior)

4 tarjetas métricas que resumen el estado actual del negocio:

| KPI | Métrica | Trend | Target |
|---|---|---|---|
| **Producción Total** | Toneladas cosechadas (campaña actual) | ↑/↓ vs campaña anterior | — |
| **Rendimiento Promedio** | t/ha (campaña actual) | ↑/↓ vs campaña anterior | 70+ t/ha |
| **Superficie Activa** | Hectáreas en producción | — (valor absoluto) | — |
| **Costo por Tonelada** | $/t (campaña actual) | ↑/↓ vs campaña anterior | — |

**Reglas de KPI:**
- El KPI más relevante para el usuario según la época del año se destaca visualmente (ligeramente más grande o con acento de color).
- Cada KPI es clickable → lleva a la pantalla de detalle correspondiente.
- En hover sobre el trend, tooltip con valor exacto anterior y período comparado.

#### Bloque 2: Mapa + Clima (fila central)

**Mapa (8 columnas):**
- Muestra todas las parcelas del productor.
- Por defecto: coloreadas por rendimiento estimado (heatmap verde-dorado).
- Capas disponibles (toggle): rendimiento, variedad, actividades recientes, alertas, NDVI.
- Click en parcela: selecciona y abre side panel con detalle.
- Zoom: centrado automático en el conjunto de parcelas.

**Clima (4 columnas):**
- Widget compacto con: temperatura actual, ícono, sensación térmica, máxima/mínima del día.
- Pronóstico: 5 días siguientes en miniatura (solo ícono + temp max/min).
- Alerta climática activa (si existe) con color warning.
- Click → pantalla de clima completa.

#### Bloque 3: Alertas Activas (ancho completo)

Lista de alertas activas, priorizadas:
- **Críticas (error-500):** Helada inminente, plaga detectada, incendio cercano.
- **Importantes (warning-500):** Umbral de riego próximo, fertilización pendiente.
- **Informativas (info-500):** Reporte generado, dato sincronizado.

Máximo 3 alertas visibles. "Ver todas" si hay más. Cada alerta es actionable (click → acción sugerida).

#### Bloque 4: Gráficos (fila inferior)

**Producción por Campo (6 columnas):**
- Gráfico de barras horizontal.
- Cada barra = un campo.
- Ordenado de mayor a menor producción.
- Color brand-500.
- Tooltip con producción en t y rendimiento en t/ha.

**Costos por Categoría (6 columnas):**
- Donut chart.
- Categorías: Labores, Insumos, Cosecha, Transporte, Otros.
- Label central con total.
- Click en segmento → desglose.

**Rendimiento Histórico (6 columnas):**
- Gráfico de líneas.
- Eje X: campañas (5 años).
- Eje Y: rendimiento t/ha.
- Línea brand-500 + área con gradiente sutil.
- Línea punteada de meta (target 70 t/ha).

**Actividad Reciente (6 columnas):**
- Timeline vertical con últimas actividades.
- Ícono + timestamp + descripción.
- Link "Ver toda la actividad".

#### Bloque 5: Asistente IA (ancho completo, parte inferior)

- Input de chat natural: "Pregúntale a SmartCaña..."
- 3 sugerencias rápidas como chips clickables.
- Últimos mensajes del asistente (máximo 3 visibles, expandible).
- Estilo diferenciado: borde purple sutil, fondo ligeramente distinto.
- Indicador de "pensando" con dots animados purple.

### 8.4 Estados del Dashboard

| Estado | Comportamiento Visual |
|---|---|
| **Cargando** | Skeleton screens en cada bloque. No spinners gigantes. |
| **Cargado** | Transición suave de skeleton a contenido (200ms crossfade). |
| **Vacío (primer uso)** | Hero ilustrativo + onboarding: "Bienvenido a SmartCaña. Comienza agregando tu primer campo." |
| **Error de carga** | Card de error en el bloque fallido. No colapsa todo el dashboard. |
| **Refrescando** | Indicador sutil en header ("Actualizando...") + pull-to-refresh. |
| **Datos desactualizados** | Badge "Desactualizado" + timestamp de última actualización. |

## 10. Flujo UX

### 10.1 Principio de Navegación

SmartCaña sigue el principio de **navegación plana** (flat navigation). El usuario nunca está a más de 2 clics de cualquier funcionalidad principal.

### 10.2 Flujo del Usuario al Abrir la Plataforma

```
1. LOGIN
   │
   ├─ ¿Primera vez? → Onboarding (3 pasos):
   │   1. Agregar primer campo (nombre + dibujar en mapa)
   │   2. Configurar datos básicos (variedad, superficie)
   │   3. Invitar a miembros del equipo (opcional)
   │
   └─ Usuario existente → DASHBOARD
       │
       ├─ Ve KPIs en 2 segundos
       ├─ Ve mapa con parcelas
       ├─ Ve alertas activas (si existen)
       │
       ├─ Click en parcela del mapa → Side panel con info
       │   ├─ Click "Ver detalle" → Detalle del Campo
       │   └─ Click "Nueva actividad" → Modal actividad
       │
       ├─ Click en alerta → Acción sugerida
       │
       ├─ Click en KPI → Pantalla de detalle (Producción/Costos)
       │
       └─ Click en IA → Chat asistente
```

### 10.3 Flujo de Registro de Actividad (Uso Diario Más Común)

```
1. Usuario abre SmartCaña
2. Ve dashboard + alertas
3. Click en "Campos" en sidebar
4. Selecciona parcela en mapa o lista
5. Click "Nueva Actividad" desde toolbar o panel
6. Modal aparece:
   - Paso 1: Tipo de actividad (cosecha/fertilización/riego/control)
   - Paso 2: Datos específicos (según tipo)
   - Paso 3: Confirmar y guardar
7. Actividad queda registrada
8. Dashboard se actualiza automáticamente
```

**Tiempo estimado:** 20-35 segundos para registrar una actividad completa.

### 10.4 Flujo de Consulta IA

```
1. Usuario en cualquier pantalla
2. Click en IA (sidebar) o botón flotante de IA
3. Input de lenguaje natural
4. SmartCaña procesa la consulta + contexto actual
5. Respuesta con datos,
```

graficos o acciones sugeridas
6. Usuario puede hacer follow-up questions
7. La conversación se guarda y puede retomarse

**Tiempo estimado:** 5-10 segundos para obtener respuesta.

### 10.5 Estrategia de Reducción de Clics

| Principio | Aplicación |
|---|---|
| **Acciones inline** | Editar nombre de campo directamente en la lista, sin abrir modal |
| **Bulk actions** | Seleccionar múltiples actividades y cambiar estado/categoría en batch |
| **Keyboard shortcuts** | `N` nueva actividad, `F` buscar, `M` toggle mapa, `1-4` atajos a secciones |
| **Persistencia de contexto** | Volver de detalle a lista preservando filtros y scroll |
| **Predictive search** | Mientras escribe, resultados aparecen en < 200ms |
| **Defaults inteligentes** | Al crear actividad, preseleccionar el campo que el usuario está viendo |
| **Undo** | Toda acción destructiva tiene 5 segundos de undo |

### 10.6 Cómo Mejorar Productividad

1. **Atajos de teclado visibles** — Mostrar `⌘N` al lado del botón "Nuevo" (tooltip).
2. **Plantillas de actividades** — Presets para tareas recurrentes (ej: "Fertilización estándar Lote 4").
3. **Autocompletado inteligente** — Al escribir "Lote 4" en cualquier campo, autocompletar datos.
4. **Recordatorios automáticos** — Basados en historial: "La última fertilización fue hace 45 días. ¿Desea programar la próxima?"
5. **Reportes con un clic** — Botón flotante "Exportar" visible en todas las pantallas con datos tabulares.
6. **Sincronización en segundo plano** — Datos se guardan automáticamente. Sin botón "Guardar" en formularios simples.

## 11. Responsive

### 11.1 Desktop (>1280px)

- Sidebar expandida (256px).
- Dashboard en grid de 12 columnas.
- Split views funcionales (lista + mapa, chat + contexto).
- Máxima densidad de información.

### 11.2 Notebook (1024-1279px)

- Sidebar colapsada a iconos (64px).
- Dashboard reduce a 2 columnas en ciertos bloques.
- Split views se mantienen pero con menos espacio para cada panel.
- Tooltips en lugar de labels persistentes en sidebar.

### 11.3 Tablet (768-1023px)

- Sidebar se convierte en drawer (hamburger menu).
- Dashboard en 1 columna.
- KPIs en grid de 2×2.
- Mapa ocupa ancho completo, widgets debajo.
- Split views se rompen: tabla ocupa todo, mapa accesible por tab.
- IA: responsive, input full width.

### 11.4 Mobile (<768px)

- Navegación bottom tab bar (4-5 iconos principales).
- Dashboard: KPIs en 2 columnas, luego cada bloque en 1 columna.
- Mapas: ancho completo, controles táctiles agrandados.
- Tablas: scroll horizontal con primera columna sticky.
- Modales: full-screen (slide from bottom) en lugar de centered modal.
- IA: input fijo abajo, chat full height.
- Botones: touch targets mínimos 44px.
- Sidebar: remplazada por bottom navigation + drawer para más opciones.

### 11.5 Comportamientos Adaptativos

| Componente | Desktop | Tablet | Mobile |

## 12. Accesibilidad

### 12.1 Estándar

SmartCaña cumple con **WCAG 2.1 Level AA** como mínimo. Se busca AA+ en componentes críticos (login, dashboard, navegación).

### 12.2 Contraste

| Combinación | Ratio Mínimo | Auditado |
|---|---|---|
| Texto normal sobre fondo | 4.5:1 | ✅ Todos los pares de la paleta |
| Texto grande (>18px bold o >24px) | 3:1 | ✅ KPIs, títulos |
| UI components (bordes, iconos) | 3:1 | ✅ Botones, inputs, badges |
| Estados hover/focus | 3:1 sobre estado base | ✅ |

**Herramienta de verificación:** Contrast Checker integrado en el proceso de diseño. Todos los tokens de color fueron validados.

### 12.3 Teclado

- Toda funcionalidad accesible por teclado.
- Orden de tabulación lógico (left-to-right, top-to-bottom).
- Skip to main content link al inicio de cada página.
- Focus visible siempre (`shadow-ring` en brand-500).
- Sin focus traps en modales (escape cierra, tab dentro del modal).
- Atajos de teclado documentados y configurables.

### 12.4 Lectores de Pantalla

- Todos los iconos decorativos tienen `aria-hidden="true"`.
- Todos los iconos funcionales tienen `aria-label` descriptivo.
- Gráficos Recharts: `role="img"` con `aria-label` describiendo la tendencia.
- Mapas Leaflet: `aria-label` en el contenedor, descripción textual de elementos visibles.
- Tablas: headers semánticos (`<th>` con scope), `aria-sort` en columnas ordenables.
- Formularios: labels asociados, mensajes de error con `aria-describedby` o `role="alert"`.
- Modales: `role="dialog"`, `aria-modal="true"`, focus trap, `aria-labelledby` en título.
- Loading: `aria-busy="true"` en contenedores, spinners con `role="status"`.
- Notificaciones toast: `role="alert"`, `aria-live="polite"`.

### 12.5 Otras Prácticas

- **Idioma:** `lang="es-AR"` en `<html>`.
- **Zoom:** Permitir zoom hasta 200% sin pérdida de contenido.
- **Motion:** `prefers-reduced-motion` respetado (desactivar animaciones, transiciones instantáneas).
- **Color:** Ninguna información se transmite solo por color (siempre hay icono + texto).
- **Target size:** Mínimo 44×44px para touch targets en mobile.

## 13. Animaciones

### 13.1 Filosofía de Movimiento

Las animaciones en SmartCaña son **funcionales, no decorativas**. Cada animación tiene un propósito:

1. **Atraer atención** (alerta nueva, notificación).
2. **Explicar cambio** (elemento aparece/desaparece, layout cambia).
3. **Mejorar percepción de performance** (skeleton loading, transiciones instantáneas).
4. **Dar feedback** (hover, active, success).
5. **Guiar la mirada** (scroll reveal, stagger).

### 13.2 Motion Principles

| Principio | Explicación |
|---|---|
| **Rápido** | 150-300ms para microinteracciones. El usuario no espera. |
| **Natural** | Curvas easing basadas en movimiento físico. `ease-out` para entradas, `ease-in-out` para transiciones. |
| **Continuo** | Elementos no desaparecen/ aparecen sin transición. Siempre hay fade, scale o slide. |
| **Sutil** | Sin animaciones llamativas. Sin bounce, sin elastic, sin ruido visual. |
| **Reducible** | `prefers-reduced-motion` desactiva todo movimiento no esencial. |

### 13.3 Timing y Easing

| Contexto | Duración | Easing |
|---|---|---|
| Hover / Active | 100-150ms | `ease-out` |
| Microinteracciones | 150-200ms | `ease-out` |
| Transiciones de página | 200-300ms | `ease-in-out` |
| Modales / Drawers | 200-300ms | `ease-out` |
| Skeleton loading | 800-1200ms (loop) | Linear |
| Stagger children | 50-80ms delay entre items | — |
| Scroll reveal | 300-400ms | `ease-out` |
| Notificaciones toast | 300ms entrada, 5000ms visible, 300ms salida | `ease-in-out` |

### 13.4 Microinteracciones

| Elemento | Animación |
|---|---|
| **Botón hover** | Fondo cambia de color (150ms). Sin escala ni movimiento. |
| **Botón active** | Escala 0.98 (100ms) + fondo más oscuro. |
| **Botón loading** | Spinner replace icon (opacity crossfade 150ms). |
| **Checkbox toggle** | Slide + fill (200ms), check mark draw (150ms). |
| **Input focus** | Borde transiciona a brand-500 (150ms), shadow-ring aparece. |
| **Input error** | Borde transiciona a error-500 (150ms), shake sutil (50ms × 3). |
| **Badge count** | Número escala 1.2 y vuelve a 1 (200ms) cuando incrementa. |
| **Link hover** | Underline aparece desde centro (200ms). |

### 13.5 Scroll

- **Scroll suave** nativo (`scroll-behavior: smooth`).
- **Scroll reveal** sutil para bloques de dashboard: fade + translateY(8px) → translateY(0) (opacity 0→1). Stagger de 80ms entre bloques. Solo en carga inicial, no en scroll continuo.
- **Sticky headers** en tablas con sombra sutil al hacer scroll.

### 13.6 Hover

| Elemento | Efecto |
|---|---|
| Card clickable | Sombra aumenta de `shadow-md` a `shadow-lg` (200ms). |
| Tabla row | Fondo cambia a `bg-subtle` (100ms). |
| Sidebar item | Background tint + text opaco (150ms). |
| Chart point | Tooltip aparece con fade (100ms). |
| Map parcel | Borde se ilumina, fill se intensifica (150ms). |
| KPI | Trend label se vuelve más visible (100ms). |

### 13.7 Loading States

| Estado | Visual |
|---|---|
| **Skeleton** | Rectángulos grises con shimmer (gradiente animado en 1.2s loop). Misma forma que el contenido final. |
| **Skeleton card** | Rectángulo con border-radius del componente, líneas simulando texto. |
| **Skeleton chart** | Rectángulo del tamaño del chart, sin shimmer (para no distraer mientras carga). |
| **Spinner** | Círculo animado rotando (600ms loop). Stroke width 4px, color brand-500. Solo usado en botones. |
| **Progress bar** | Línea horizontal delgada (3px), animación indeterminate (1.5s loop). Para carga de archivos. |
| **Page load** | Skeleton de toda la página. No spinner gigante ni pantalla blanca. |

### 13.8 Transiciones

| Contexto | Animación |
|---|---|
| **Página cambia** | Fade out/in (200ms). No slide. No flash. |
| **Sidebar expand/colapsa** | Width animado (200ms), contenido fade in/out (100ms). |
| **Modal abre** | Overlay fade in (200ms) + modal scale 0.95→1 (250ms). |
| **Modal cierra** | Overlay fade out (150ms) + modal scale 1→0.95 (150ms). |
| **Dropdown abre** | Scale Y 0.95→1 + opacity 0→1 (150ms). |
| **Drawer abre** | Slide desde derecha (250ms), overlay fade (150ms). |
| **Toast aparece** | Slide desde top+opacity (200ms). |
| **Toast desaparece** | Opacity→0 + slide up (200ms). |
| **Chart draw** | Línea se dibuja de izquierda a derecha (500ms). Barras crecen de abajo (300ms stagger 50ms). |
| **Accordion** | Height animado (200ms), rotate chevron (150ms). |
| **Tab switch** | Content fade 150ms, indicator slide 200ms. |

### 13.9 prefers-reduced-motion

Cuando `prefers-reduced-motion: reduce` está activo:

- Sin skeleton shimmer (solo estático).
- Sin animaciones de entrada.
- Transiciones instantáneas (0ms).
- Sin parallax, sin scroll reveal.
- Sin draw animation en charts (datos aparecen inmediatamente).
- Hover sigue funcionando (es esencial).
- Loading spinners siguen funcionando (es información de estado).

1. **Global tokens** — Valores primitivos (colores HEX, spacing en rem).
2. **Alias tokens** — Semántica contextual (`color.bg.surface`).
3. **Component tokens** — Específicos de componente (`button.primary.bg`).

## 15. Principios de UX

### 15.1 Principio 1: El Productor No Lee, Escanea

Los productores cañeros no pasan horas frente a una computadora. Usan SmartCaña en momentos específicos del día (mañana temprano, después del recorrido de campo, antes de cenar). La interfaz debe ser **escanable en 3 segundos**:

- Títulos claros y jerarquía visual fuerte.
- KPIs y métricas visibles sin scroll.
- Alertas destacadas con color + icono.
- Acciones principales visibles sin búsqueda.

### 15.2 Principio 2: Datos Primero, Luego Acciones

Cada pantalla muestra primero los datos relevantes, luego las acciones disponibles. El usuario no debe decidir qué hacer sin antes ver el estado actual.

- Dashboard: KPIs → Mapa → Alertas → Gráficos → Acciones.
- Detalle de campo: Métricas → Mapa → Datos → Historial → Acciones.
- Producción: Totales → Gráficos → Tabla → Exportar.

### 15.3 Principio 3: Menos es Más

Cada elemento en pantalla compite por la atención del usuario. SmartCaña elimina todo lo que no es esencial:

- Sin carruseles, sin rotación de banners, sin "tips del día".
- Sin decoración visual gratuita (íconos decorativos, ilustraciones sin propósito).
- Sin confirmaciones innecesarias ("¿Está seguro de que quiere guardar?").
- Sin opciones duplicadas (una acción, un botón).

### 15.4 Principio 4: Error es una Oportunidad

Los errores no son culpa del usuario. SmartCaña:

- Explica qué pasó en lenguaje simple (no técnico).
- Sugiere la siguiente acción ("No pudimos cargar los campos. ¿Quiere reintentar?").
- Preserva los datos ingresados (nunca perder el formulario por un error de red).
- Ofrece undo para acciones destructivas.

### 15.5 Principio 5: Offline First (Resiliencia)

El campo argentino no tiene internet confiable. SmartCaña:

- Opera en modo offline: datos locales, sincronización cuando vuelve la conexión.
- Indicador visual de estado de conexión (online / offline / syncing).
- Sin pérdida de datos por caída de conexión.
- Carga progresiva: primero lo visible, después el resto.

### 15.6 Principio 6: Consistencia Radical

- Mismo color = mismo significado en toda la plataforma.
- Mismo icono = mismo concepto (nunca dos iconos para un mismo concepto).
- Misma posición de elementos (botón de acción siempre en la misma esquina).
- Mismo comportamiento (click siempre selecciona, nunca abre un menú contextual inesperado).
- Misma nomenclatura en toda la UI (una parcela es siempre un "campo", nunca "lote" en un lado y "parcela" en otro).

### 15.7 Principio 7: La IA es Asistente, no Protagonista

SmartCaña usa IA para potenciar al productor, no para reemplazar su juicio:

- La IA sugiere, no decide. El productor siempre tiene la última palabra.
- Las sugerencias de IA son transparentes ("Basado en los datos históricos...").
- La IA se ofrece, no se impone (input de chat, no popup automático).
- La IA responde en contexto (sabe qué pantalla está viendo el usuario).

### 15.8 Principio 8: Cada Pantalla Tiene un Propósito Único

Si una pantalla intenta hacer dos cosas diferentes, se divide en dos pantallas.

- Dashboard: estado actual + alertas + acceso rápido.
- Campos: gestión geoespacial de parcelas.
- Actividades: registro y consulta de operaciones.
- Producción: análisis de rendimiento.
- Costos: control financiero.
- IA: consultas y análisis inteligente.

No hay pantallas "multipropósito". Cada una resuelve un trabajo específico.

### 15.9 Principio 9: Performance es UX

Una interfaz lenta es una mala interfaz, sin importar cómo se vea:

- Primer paint del dashboard: < 1.5s.
- Transiciones de página: < 300ms.
- Búsqueda: resultados en < 200ms (debouncing + indexación local).
- Carga de mapa: < 2s (tiles precargados, polígonos simplificados).
- Chat IA: respuesta streamada (el usuario ve el texto mientras se genera).
- Skeleton loading siempre presente (nunca blank screen).

### 15.10 Principio 10: Diseñar para el Próximo Paso

Cada pantalla anticipa lo que el usuario querrá hacer después:

- Después de guardar una actividad: "¿Desea registrar otra en el mismo campo?"
- Después de ver un KPI bajo: link a "Analizar causas con IA".
- Después de exportar un reporte: "¿Programar este reporte semanalmente?"
- Después de agregar un campo: "¿Desea definir las variedades?"
- Después de un error: acción de reintento o contacto con soporte.

## Apéndice C: Integración con la Arquitectura

El design system se implementa en el frontend (Next.js) mediante:

- **Tailwind CSS** con configuración extendida de colores, fuentes, spacing, radius y shadows.
- **shadcn/ui** como base de componentes, customizados con los tokens de SmartCaña.
- **CSS Variables** para modo claro/oscuro: `:root` y `.dark` o `[data-theme="dark"]`.
- **Framer Motion** para animaciones y transiciones.
- **Lucide React** para iconografía.
- **Recharts** con tema personalizado usando los tokens de chart.

La implementación de estos componentes y la configuración de Tailwind se documentará en la fase de desarrollo. Este documento es la especificación de diseño que guiará toda la implementación frontend.
